# Project Indexer — Knowledgebase

Reference for how the app works and why it's built this way. Unlike `accomplishments.md`, this file describes current state, not history — update it in place as things change rather than appending. See `checklist.md` for what's still open.

## What this is

A Tauri v2 desktop app (Rust backend, Svelte 5 + SvelteKit + Tailwind v4 frontend) for tracking local project directories: register a directory as a "project," tag/favorite it, launch it in a chosen app or the file explorer, soft-delete/restore it via a bin, and see what kind of project it is (git, Unreal, ...) via per-project detection. Single-instance, with window-state persistence and a global shortcut plugin wired in (shortcut itself not yet bound to an action).

## Backend architecture (`src-tauri/src/`)

- `models/` — `Project` (`trackers: Vec<Tracker>`), `UpdateProject` (partial-update DTO with a double-`Option` deserializer to distinguish "omit field" from "set to null"), `Tracker` (enum: `Git(GitInfo)` / `Unreal(UnrealInfo)` — a variant exists only if a detector can produce it, so a new variant lands together with its detector), `GitInfo`, `UnrealInfo`, `InstalledApp`. `GitInfo` carries `web_url: Option<String>` alongside `repo_url` — the browser-openable form of the remote (SSH/`git@`/`ssh://` and `https://` all normalized to `https://host/owner/repo`, trailing `.git` stripped), derived by `Gitector` so the frontend gets a working "open remote" link without parsing URLs itself; `None` when the remote isn't a recognizable http/ssh git URL.
- `commands/` — `projects.rs` (CRUD, open/delete/restore/untrack, plus detection — see "Tracker detection" below), `system.rs` (installed-app discovery for the "open with" picker, directory removal, app-launch helpers with separate Windows/Linux implementations; macOS still unimplemented), and `inspect.rs` (`inspect_project` — a read-only "load a project and run detection live against its directory" for the `/project/[id]` view; returns a `ProjectInspection { project, directory_status, results }` and never touches the store — `refresh_project_trackers` stays the only write path).
- `store/` — `ProjectStore`, a thin wrapper over `tauri-plugin-store` (a JSON k/v file, `projects.json`) with an autosave debounce; `ProjectStore::flush()` is called explicitly on window close to avoid losing last-second writes. Chosen over always-explicit `.save()` because the plugin's default autosave already debounces writes — see the reasoning in the project's memory (`project_store_save_strategy`) if that trade-off needs revisiting.
- `migrations/` — a `schema_version`-stamping migration pipeline for the stored JSON. Currently a no-op beyond stamping (`CURRENT_VERSION = 1`), but the seam exists for future field renames/type changes that `#[serde(default)]` can't absorb.
- `utils/` — `filesystem.rs` (directory status checks), `sorting.rs` (`sort_projects`, alphabetical/last-opened with direction, favorite/deleted filters), `normalize.rs` (directory-path normalization, tag normalization, space-stripping — free functions, each independently unit-tested).
- `detectors/` — the `Detector` trait (`detector.rs`: two methods — `kind(&self) -> &'static str`, a stable lowercase identity like `"git"` / `"unreal"`, and `detect(&Path) -> Result<Option<Tracker>, DetectorError>`), a `DetectorRunner` (`runner.rs`) whose `detect_project(&Path) -> Detection` is the canonical detection operation (`inspect(&Path, only: Option<&str>)` is the same pass restricted to one detector `kind`, backing per-tracker re-detect), and `registry.rs` (`default_detectors()`), the single place detectors are registered (`Gitector`, `UnrealDetector`). `detect_project` is infallible by construction: it runs every detector and collects a `Detection { outcomes: Vec<DetectorOutcome> }`, one `DetectorOutcome::{Detected { kind, tracker } | NotDetected { kind } | Failed { kind, error }}` per detector consulted, so one detector erroring neither stops the others nor discards their trackers. `Detection::trackers()` / `errors()` project those back out; `Detection::into_result()` gives the all-or-nothing view for callers that persist (unchanged semantics — first failure discards partial trackers, guarded by `into_result_discards_partial_trackers_on_any_error`). The app builds one `DetectorRunner` at startup into Tauri managed state; commands take `State<'_, DetectorRunner>`.
- `errors/` — `ProjectError` (surfaced to the frontend as a plain string), `GitError`, `UnrealError`, `DetectorError` (`Io`/`Git`/`Unreal` typed variants plus an `Other(Box<dyn Error + Send + Sync>)` catch-all so a new detector needn't edit the enum; converted to `ProjectError::Detection` at the command boundary).

## Frontend architecture (`src/`)

- SvelteKit with static adapter, Tailwind v4. `+page.svelte` is the main list view; there's one other route, `/project/[id]` (`src/routes/project/[id]/+page.svelte` + `+page.ts` with `prerender = false`), the per-project detail view. Feature UI is split into modals/components: `CreateProjectForm`, `EditProjectForm`, `ProjectList`/`ProjectCard`, `ProjectIdentity`, `TrackerPanel`, `TrackerBadges`, `BinModal`, `FavoritesModal`, `DeleteModal`, `AppPicker`, `OpenWithMissingModal`, `DirectoryField`, `SortControls`, `ErrorBanner`.
- The `/project/[id]` view replaces the old `ProjectDetailModal` (deleted). It calls `inspect_project` on open for a live, read-only detection pass, renders `ProjectIdentity` (the identity `<dl>`, lifted out of the modal) plus a per-detector status strip, and one tab per detected tracker rendered by the generic `TrackerPanel`. Per-tab **re-detect** re-runs a single detector (`inspect_project`'s `only`); **Edit** opens `EditProjectForm` in an overlay; **Refresh** is the one action that persists (`refresh_project_trackers`). "Details" on `ProjectCard` is now a plain `<a href="/project/{id}">`.
- `lib/trackers.ts` — `trackerKind()` reads a tracker's variant name off its serde shape (`{ Git: {...} }`, or a bare string for a future unit variant); `trackerFields()` returns typed fields (`text` / `code` / `link` / `path` / `chips` / `flag`) inferred from each key's name and value shape — an `http(s)://` value is a `link`, an `ssh` / `git@` value is copyable `code`, `*_root` / `*_path` / `*_dir` keys are `path`, `*hash*` / `*commit*` keys are `code`, arrays are `chips`, booleans are `flag` (shown only when true), everything else is `text`. Zero per-tracker-kind code. `TrackerPanel` (on `/project/[id]`) consumes `trackerFields()` and renders each field type with open / reveal / copy affordances (clipboard failure is swallowed; open/reveal failure raises a banner). `TrackerBadges` (list cards) and the route's tab labels use `trackerKind()` only.
- `lib/api/` mirrors backend commands 1:1: `projects.ts` (`inspectProject` added), `apps.ts`, `types.ts` (hand-mirrors the Rust structs, incl. `GitInfo.web_url` and the `ProjectInspection` / `DetectorResult` / `DirectoryStatus` DTOs), `errors.ts` (normalizes thrown values), `opener.ts` (`openExternalUrl` + `revealPath` wrap the `@tauri-apps/plugin-opener` `openUrl` / `revealItemInDir`).
- `app.css` declares `color-scheme: light dark` on `<html>` so native widgets (selects, scrollbars, spinners) follow the active theme — see `KNOWN-ISSUES.md` PI-001 for why this was needed.
- Two frontend checks: `svelte-check` (`npm run check`) and `vitest` (`npm test`, config in `vite.config.js`). `src/lib/trackers.test.ts` covers the `trackers.ts` field-type inference.

## Domain model (`Project`)

Fields: `id`, `name`, `description`, `directory`, `created_at`/`updated_at`, `last_opened_at`, `tags`, `favorite`, `open_with`, `notes`, `client`, `is_deleted`, `trackers: Vec<Tracker>` (defaults to empty via `#[serde(default)]`, not `Option`).

Invariants (see doc comments in `project.rs`):

- New fields must be `Option<T>` or `#[serde(default)]` so old stored records keep loading — enforced by a test that deserializes a "legacy record" missing every optional field.
- `id`/`directory` are strict — a record missing either fails to load rather than loading blank.
- Directory and name uniqueness checks happen at creation via directory-path normalization (`utils/normalize.rs`) so `C:\Foo\` and `C:/Foo` collide correctly; case is deliberately _not_ normalized.
- Soft-delete: `delete_project_directory` removes the directory from disk and either purges metadata immediately or marks `is_deleted` for the bin; `delete_project` (metadata-only purge) refuses to run on a project that isn't already soft-deleted; `untrack_project` drops tracked metadata without touching the directory at all, usable on any project regardless of `is_deleted`.

## Tracker detection, end to end

Every entry point calls the same `DetectorRunner` (pulled from managed state) and differs only in what it does with the `Detection`:

1. `create_project` — best-effort: `detection.trackers()` are kept, `detection.errors()` are logged not surfaced, since the project is still worth tracking. Resilient, so a git hiccup doesn't cost you an Unreal tracker on the same directory.
2. `refresh_project_trackers` — all-or-nothing (`Detection::into_result`): checks directory health first (a moved directory gets its own clear error), then any detector failure is surfaced and the stored trackers are left untouched. It's an explicit user-triggered retry, so a half-applied refresh would be more confusing than a clear failure. Deliberate — see `architecture.md` "Recorded decisions" for the rejected alternative (persist successes, keep per-detector errors). **This is the only path that writes trackers back to the store.**
3. `detect_project_trackers` — advisory preview against a directory that isn't a project yet; nothing touches the store. Best-effort like `create_project`; returns `Vec<Tracker>` directly. Backs the browse-autocomplete flow below.
4. `inspect_project` — the `/project/[id]` view's read: loads the stored project, then runs a **live** detection pass (`DetectorRunner::inspect`, all detectors or just `only` on a per-tab re-detect) against its directory and returns every `DetectorResult { kind, status, tracker?, error? }` plus a `directory_status`. Read-only — a live re-scan for display, deliberately not persisted; the user commits it with Refresh (path 2). A missing/inaccessible directory comes back as `directory_status.ok = false` with empty results, not a command error, so the view can still show the project's identity.
5. Two real detectors are registered (in `detectors/registry.rs`):
   - `Gitector` — repo root, dirty (untracked + modified, not ignored), detached-HEAD, remote URL (`origin`), current branch (handles the unborn-HEAD case for a fresh repo with no commits), every local branch, HEAD commit hash. `contributors` is deliberately left `Vec::new()` — see `checklist.md`.
   - `UnrealDetector` — finds the `.uproject` file directly inside a directory (not discovered upward like git), parses its JSON for engine association/category/description/modules/enabled plugins, and reads the configured source-control provider from `Saved/Config/<Platform>Editor/SourceControlSettings.ini` (a per-user file most `.gitignore`s exclude, so `None` on a fresh clone is the common case, not a bug).
6. **Browse-to-prefill:** picking a directory in `CreateProjectForm` calls `detect_project_trackers` and suggests a name (git remote's repo name, else the folder name) — only while Name is still empty, and silently skipped on any detection failure.
7. **Project detail view:** `ProjectCard`'s "Details" link opens `/project/[id]`, which calls `inspect_project` (path 4) — `ProjectIdentity` up top, a per-detector status strip, then one tab per detected tracker rendered generically by `TrackerPanel` (`lib/trackers.ts`).

## Test coverage

61 Rust unit tests (`cargo test --lib` in `src-tauri/`, on Windows; a few more Linux-only), covering: directory/tag normalization, duplicate detection, directory health checks, soft-delete/restore/untrack, legacy-record migration compatibility, sorting (alphabetical/last-opened, both directions, tie-breaking), favorite/deleted filtering, installed-app availability checks, (Linux-only) `.desktop` exec-string parsing/launching, git detection (repo/non-repo, unborn HEAD, committed HEAD, dirty state, remote URL, multiple branches, detached HEAD, `web_url` normalization of `git@` / `ssh://` / `https://` remote forms, `Detector::kind()`), Unreal detection (`.uproject` discovery, descriptor parsing incl. missing-field defaults, source-control provider incl. an explicit `Provider=None`, `Detector::kind()`), detector-runner behaviour (`Send + Sync`, `DetectorOutcome` per detector, `inspect` running only the named detector, one detector failing without discarding the others' trackers, `into_result` all-or-nothing in both directions), and `inspect.rs`'s `results_from` mapping every `DetectorOutcome` variant to its `DetectorResult`. No integration tests against the Tauri command layer itself. Frontend: `svelte-check` (`npm run check`) plus a `vitest` suite (`npm test`) — `src/lib/trackers.test.ts`, 10 tests over the `trackers.ts` field-type inference (http URL → link, ssh remote → code not a broken link, `*_root`/`*_path` → path, commit-hash → code, arrays → chips with empties dropped, true bool → flag / false hidden, null/empty omitted, text fallback).

## Dependencies of note

`git2` (libgit2 bindings, used by `Gitector`), `serde_json` (Unreal `.uproject` parsing), `chrono`, `uuid`, `thiserror`, `tauri-plugin-store/dialog/shell/opener/global-shortcut/single-instance/window-state`. Windows-only: `winreg`, `parselnk` (Start Menu `.lnk` resolution for the app picker).

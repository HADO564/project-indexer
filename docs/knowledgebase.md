# Project Indexer — Knowledgebase

Reference for how the app works and why it's built this way. Unlike `accomplishments.md`, this file describes current state, not history — update it in place as things change rather than appending. See `checklist.md` for what's still open.

## What this is

A Tauri v2 desktop app (Rust backend, Svelte 5 + SvelteKit + Tailwind v4 frontend) for tracking local project directories: register a directory as a "project," tag/favorite it, launch it in a chosen app or the file explorer, soft-delete/restore it via a bin, and see what kind of project it is (git, Unreal, ...) via per-project detection. Single-instance, with window-state persistence and a global shortcut plugin wired in (shortcut itself not yet bound to an action).

## Backend architecture — a Cargo workspace

Three crates. `indexer-core` (`crates/core`) holds every bit of domain logic,
orchestration and persistence and has **no `tauri` dependency** (a `use tauri::`
in it fails to compile). `src-tauri` is a thin GUI adapter over it. `crates/cli`
(`indexer-cli`) is a one-line stub — `eprintln!("… not implemented (spec 2)")`,
exit 1 — reserving the layout for a future observer CLI (Spec 2).
`src-tauri → indexer-core`, never the reverse.

### `crates/core` (`indexer-core`)

- `domain/` — `Project` (`trackers: Vec<Tracker>`), `UpdateProject` (partial-update DTO with a double-`Option` deserializer to distinguish "omit field" from "set to null"), `Tracker` (enum: `Git(GitInfo)` / `Unreal(UnrealInfo)` — a variant exists only if a detector can produce it), `GitInfo` (carries `web_url: Option<String>` alongside `repo_url` — the browser-openable form of the remote, SSH/`git@`/`ssh://` and `https://` normalized to `https://host/owner/repo` with trailing `.git` stripped; `None` when unrecognizable), `UnrealInfo`, `InstalledApp`. Plus `normalize` (directory-path / tag normalization — free, independently unit-tested functions), `sorting` (`sort_projects`, alphabetical/last-opened with direction, favorite/deleted filters), and `naming` (`repo_name_from_url` / `folder_name_from_directory` / `suggest_project_name` — ported from `CreateProjectForm.svelte`, so the "name a project from its git remote or folder" logic is Rust-side and unit-tested; backs the `suggest_project_name` command).
- `ports/` — the two traits the service depends on. `ProjectReader` (`get` / `list` / `find_by_directory` — the read half, split out so an external consumer like devmon can depend on read access alone) and `ProjectRepository: ProjectReader` (`save` upsert-by-id / `delete` idempotent). `AppLauncher` (`open(directory, open_with)` / `is_available(open_with)`). `Detector` already existed.
- `application/` — `ProjectService`, the orchestration lifted verbatim out of the old Tauri commands: one method per command (`create`, `update`, `get`, `list` / `list_deleted` / `list_favorites`, `list_missing_directories`, `refresh_trackers`, `preview_detection`, `inspect`, `delete`, `restore`, `untrack`, `delete_directory`, `open`, `open_in_explorer`) plus `find_by_directory` and `ensure_project` added for Spec 2. Holds `Arc<dyn ProjectRepository>` + `Arc<dyn AppLauncher>` + `Arc<DetectorRunner>`. Also `inspection` — `ProjectInspection { project, directory_status: DirectoryState, results: Vec<DetectorResult> }` and `results_from` (moved from `commands/inspect.rs`; `DirectoryStatusDto` renamed to `DirectoryState` to drop the clash with `platform::DirectoryStatus`, JSON field still `directory_status`).
- `detectors/` — moved wholesale, zero code change. The `Detector` trait (`kind(&self) -> &'static str` stable lowercase identity + `detect(&Path) -> Result<Option<Tracker>, DetectorError>`), `DetectorRunner` (`detect_project(&Path) -> Detection` is the canonical operation; `inspect(&Path, only: Option<&str>)` is the same pass scoped to one `kind`), `registry::default_detectors()` (the one place `Gitector` / `UnrealDetector` are registered). `detect_project` is infallible: `Detection { outcomes: Vec<DetectorOutcome> }`, one `Detected { kind, tracker } | NotDetected { kind } | Failed { kind, error }` per detector. `.trackers()` / `.errors()` project them out; `.into_result()` is the all-or-nothing view (first failure discards partial trackers, guarded by `into_result_discards_partial_trackers_on_any_error`).
- `platform/` — `filesystem` (`check_directory_status` / `DirectoryStatus`, `remove_directory`) and `app_discovery` (`list_installed_apps()` dispatch, `open_with_app_available`, the Windows Start-Menu/registry scan, the Linux `.desktop` parser + `Exec=` splitting and its tests). Pure std + `winreg` + `parselnk` — not Tauri code, so it lives in `core`.
- `infra/` — `SqliteRepository` (see "Persistence") and `CURRENT_SCHEMA_VERSION`.
- `error/` — `ProjectError` (surfaced to the frontend as a plain string via a hand `Serialize` impl), `GitError`, `UnrealError`, `DetectorError` (`Io`/`Git`/`Unreal` typed variants + `Other(Box<dyn Error + Send + Sync>)` catch-all), and the two port errors: `RepositoryError` (`Backend` / `Corrupt`) and `LauncherError` — mapped in the service to `ProjectError::Store` / `ProjectError::OpenFailed`.

### `src-tauri` (GUI adapter)

- `commands/` — `projects.rs`, `inspect.rs`, `system.rs`: every `#[tauri::command]` is a ~3-line pass-through over `State<'_, Arc<ProjectService>>` (`AppHandle` gone from every signature). `system.rs` is now just `list_installed_apps` (delegating to `core::platform`). New command: `suggest_project_name`.
- `adapters/opener_launcher.rs` — `OpenerLauncher impl AppLauncher`, the one genuine adapter and the only place `tauri-plugin-opener` is still used. `open` body = the old `system.rs::open_in_app` verbatim: on Windows a concrete `open_with` executable is spawned via `std::process::Command` with `ELECTRON_RUN_AS_NODE` / `ELECTRON_NO_ATTACH_CONSOLE` scrubbed (that variable, inherited from a VS Code terminal, makes `Code.exe <folder>` run as Node and `require()` the folder); bare command names and the system-default open go through the opener plugin. `is_available` calls `core::platform::open_with_app_available`.
- `lib.rs` — the Tauri `Builder`: plugin registration, then `setup` builds `SqliteRepository::open(app_config_dir()/projects.db)` + `OpenerLauncher` + `DetectorRunner::default()` into one `ProjectService` and `app.manage(Arc::new(service))`. No `tauri-plugin-store`, no flush-on-close hook, no separate `.manage(DetectorRunner)`.

## Frontend architecture (`src/`)

- SvelteKit with static adapter, Tailwind v4. `+page.svelte` is the main list view; there's one other route, `/project/[id]` (`src/routes/project/[id]/+page.svelte` + `+page.ts` with `prerender = false`), the per-project detail view. Feature UI is split into modals/components: `CreateProjectForm`, `EditProjectForm`, `ProjectList`/`ProjectCard`, `ProjectIdentity`, `TrackerPanel`, `TrackerBadges`, `BinModal`, `FavoritesModal`, `DeleteModal`, `AppPicker`, `OpenWithMissingModal`, `DirectoryField`, `SortControls`, `ErrorBanner`.
- The `/project/[id]` view replaces the old `ProjectDetailModal` (deleted). It calls `inspect_project` on open for a live, read-only detection pass, renders `ProjectIdentity` (the identity `<dl>`, lifted out of the modal) plus a per-detector status strip, and one tab per detected tracker rendered by the generic `TrackerPanel`. Per-tab **re-detect** re-runs a single detector (`inspect_project`'s `only`); **Edit** opens `EditProjectForm` in an overlay; **Refresh** is the one action that persists (`refresh_project_trackers`). "Details" on `ProjectCard` is now a plain `<a href="/project/{id}">`.
- `lib/trackers.ts` — `trackerKind()` reads a tracker's variant name off its serde shape (`{ Git: {...} }`, or a bare string for a future unit variant); `trackerFields()` returns typed fields (`text` / `code` / `link` / `path` / `chips` / `flag`) inferred from each key's name and value shape — an `http(s)://` value is a `link`, an `ssh` / `git@` value is copyable `code`, `*_root` / `*_path` / `*_dir` keys are `path`, `*hash*` / `*commit*` keys are `code`, arrays are `chips`, booleans are `flag` (shown only when true), everything else is `text`. Zero per-tracker-kind code. `TrackerPanel` (on `/project/[id]`) consumes `trackerFields()` and renders each field type with open / reveal / copy affordances (clipboard failure is swallowed; open/reveal failure raises a banner). `TrackerBadges` (list cards) and the route's tab labels use `trackerKind()` only.
- `lib/api/` mirrors backend commands 1:1: `projects.ts` (`inspectProject`, `listMissingDirectories` added), `apps.ts`, `types.ts` (hand-mirrors the Rust structs, incl. `GitInfo.web_url` and the `ProjectInspection` / `DetectorResult` / `DirectoryStatus` DTOs), `errors.ts` (normalizes thrown values), `opener.ts` (`openExternalUrl` + `revealPath` wrap the `@tauri-apps/plugin-opener` `openUrl` / `revealItemInDir`).
- **Theme** (`app.css`): a single committed dark "terminal" look — `color-scheme: dark` (no light/dark split, which retires PI-001's bug class). The palette is semantic tokens in Tailwind v4's `@theme` (`--color-void` / `-panel` / `-line` / `-phos` / `-accent` / `-gold` / `-rust` …) — cool-slate surfaces, off-white text, cyan for anything interactive, gold for state, rust for errors. `VT323` (SIL OFL, bundled in `static/fonts/`) on chrome via `--font-display`; a system mono on data. Bordered not shadowed, 2px radius. Components use the semantic utilities (`bg-panel`, `text-phos`, …), not raw Tailwind colours.
- `lib/trackers.ts` also exports `trackerColor(kind)` — a hue per tracker kind (hand-picked for known ones, name-hashed for the rest, all fixed at `hsl(H 65% 70%)` so text always reads on the dark ground); used by `TrackerBadges`, the route's status strip and its active tab.
- `ProjectCard` folds its row actions (Open / Details / Detect / Edit / Delete) into a `···` menu, and shows an amber bin icon (path struck through) for a project whose directory is gone — driven by `list_missing_directories`, fetched once per list load.
- Two frontend checks: `svelte-check` (`npm run check`) and `vitest` (`npm test`, config in `vite.config.js`). `src/lib/trackers.test.ts` covers `trackerFields()` inference and `trackerColor()`.

## Domain model (`Project`)

Fields: `id`, `name`, `description`, `directory`, `created_at`/`updated_at`, `last_opened_at`, `tags`, `favorite`, `open_with`, `notes`, `client`, `is_deleted`, `trackers: Vec<Tracker>` (defaults to empty via `#[serde(default)]`, not `Option`).

Invariants (see doc comments in `project.rs`):

- New fields must be `Option<T>` or `#[serde(default)]` so old stored records keep loading — enforced by a test that deserializes a "legacy record" missing every optional field.
- `id`/`directory` are strict — a record missing either fails to load rather than loading blank.
- Directory and name uniqueness checks happen at creation via directory-path normalization (`core::domain::normalize`) so `C:\Foo\` and `C:/Foo` collide correctly; case is deliberately _not_ normalized.
- Soft-delete: `delete_project_directory` removes the directory from disk and either purges metadata immediately or marks `is_deleted` for the bin; `delete_project` (metadata-only purge) refuses to run on a project that isn't already soft-deleted; `untrack_project` drops tracked metadata without touching the directory at all, usable on any project regardless of `is_deleted`.

## Persistence

- `SqliteRepository` (`core::infra`) — a single `rusqlite` connection (`bundled`, so no system SQLite) behind a `Mutex`, implementing `ProjectReader` + `ProjectRepository`. `open(path)` for the real DB, `in_memory()` for tests. Every connection sets `journal_mode = WAL`, `busy_timeout = 5000`, `foreign_keys = ON`. The GUI opens it at `app_config_dir()/projects.db` — the same directory the old `tauri-plugin-store` used for `projects.json`. There is **no autosave and no flush hook**: `save` / `delete` are synchronous, committed before the call returns.
- **No migration from JSON.** The app had no production data, so first run just creates an empty `projects.db`; a leftover `projects.json` is ignored. The old `serde_json::Value`-level migration module (and its `schema_version` stamp) was deleted, not ported.
- **Schema** (`user_version = 1`): a `meta(key, value)` table seeded `('app','project-indexer')` / `('schema_version','1')` — an external reader (devmon) checks it before an `ATTACH`. A `projects` table storing the full `Project` as serde JSON in a `data` blob (source of truth) plus three promoted columns — `is_deleted`, `directory_normalized` (indexed), `updated_at` (RFC3339 UTC) — for filtering / lookup / sorting without deserializing. A `project_tags(project_id, tag)` table (indexed on `tag`, `ON DELETE CASCADE`) rewritten from `project.tags` inside the same transaction as every `save` — a derived projection for future SQL tag queries; nothing reads it back yet. `trackers` stays blob-only (normalizing a per-variant sum type would break "add a detector = zero persistence change").
- **Schema evolution** = a numbered runner keyed on `PRAGMA user_version` against `CURRENT_SCHEMA_VERSION` (a `const` in `core`). `open` migrates up to it and **refuses a DB already past it** (`RepositoryError::Backend("database is from a newer version …")`, data untouched) — the version-skew guard that makes shipping auto-updates safe. A `data`-blob that fails to deserialize is `RepositoryError::Corrupt` (fail loud).

## Tracker detection, end to end

Every entry point is a `ProjectService` method (the `DetectorRunner` is one of the service's `Arc` fields) and differs only in what it does with the `Detection`:

1. `ProjectService::create` (`create_project`) — best-effort: `detection.trackers()` are kept, `detection.errors()` are logged not surfaced, since the project is still worth tracking. Resilient, so a git hiccup doesn't cost you an Unreal tracker on the same directory.
2. `ProjectService::refresh_trackers` (`refresh_project_trackers`) — all-or-nothing (`Detection::into_result`): checks directory health first (a moved directory gets its own clear error), then any detector failure is surfaced and the stored trackers are left untouched. It's an explicit user-triggered retry, so a half-applied refresh would be more confusing than a clear failure. Deliberate — see `architecture.md` "Recorded decisions" for the rejected alternative (persist successes, keep per-detector errors). **This is the only path that writes trackers back to the store.**
3. `ProjectService::preview_detection` (`detect_project_trackers`) — advisory preview against a directory that isn't a project yet; nothing touches the store. Best-effort like `create`; returns `Vec<Tracker>` directly. Also feeds `suggest_project_name`.
4. `ProjectService::inspect` (`inspect_project`) — the `/project/[id]` view's read: loads the stored project, then runs a **live** detection pass (`DetectorRunner::inspect`, all detectors or just `only` on a per-tab re-detect) against its directory and returns every `DetectorResult { kind, status, tracker?, error? }` plus a `directory_status`. Read-only — a live re-scan for display, deliberately not persisted; the user commits it with Refresh (path 2). A missing/inaccessible directory comes back as `directory_status.ok = false` with empty results, not a command error, so the view can still show the project's identity.
5. Two real detectors are registered (in `detectors/registry.rs`):
   - `Gitector` — repo root, dirty (untracked + modified, not ignored), detached-HEAD, remote URL (`origin`), current branch (handles the unborn-HEAD case for a fresh repo with no commits), every local branch, HEAD commit hash. `contributors` is deliberately left `Vec::new()` — see `checklist.md`.
   - `UnrealDetector` — finds the `.uproject` file directly inside a directory (not discovered upward like git), parses its JSON for engine association/category/description/modules/enabled plugins, and reads the configured source-control provider from `Saved/Config/<Platform>Editor/SourceControlSettings.ini` (a per-user file most `.gitignore`s exclude, so `None` on a fresh clone is the common case, not a bug).
6. **Browse-to-prefill:** picking a directory in `CreateProjectForm` calls the `suggest_project_name` command (which runs a preview detection and then `core::domain::naming::suggest_project_name` — git remote's repo name, else the folder name) — only while Name is still empty, and silently skipped on failure. The name logic used to be inline JS in the form; it now lives in `core` and is unit-tested there.
7. **Project detail view:** `ProjectCard`'s "Details" link opens `/project/[id]`, which calls `inspect_project` (path 4) — `ProjectIdentity` up top, a per-detector status strip, then one tab per detected tracker rendered generically by `TrackerPanel` (`lib/trackers.ts`).

## Test coverage

91 Rust unit tests (`cargo test -p indexer-core`, run on Windows; +11 more `#[cfg(unix/linux)]` cases not executed there). All of it now lives in `indexer-core`; `cargo test -p project-indexer` is 0 (the GUI crate has no logic left to test). Coverage: directory/tag normalization, duplicate detection, directory health checks, soft-delete/restore/untrack, forward-compatible record shape (`loads_a_record_missing_every_absorbable_field` / `rejects_a_record_missing_its_identity` — the two legacy `serde_json::Value` migration tests were deleted with that layer), sorting (alphabetical/last-opened, both directions, tie-breaking), favorite/deleted filtering, `naming` (SSH/HTTPS remotes, `.git` suffix, trailing separators, no-remote fallback, empty), installed-app availability checks, (Linux-only) `.desktop` exec-string parsing/launching, git detection (repo/non-repo, unborn HEAD, committed HEAD, dirty state, remote URL, multiple branches, detached HEAD, `web_url` normalization, `Detector::kind()`), Unreal detection (`.uproject` discovery, descriptor parsing incl. missing-field defaults, source-control provider incl. `Provider=None`, `Detector::kind()`), detector-runner behaviour, `results_from` mapping every `DetectorOutcome` to a `DetectorResult`, `SqliteRepository` (round-trip, upsert-replaces, idempotent+cascading delete, `list` includes deleted, `find_by_directory` on the normalized index, corrupt blob → `Corrupt`, fresh DB at `user_version = 1` with `meta` seeded, refuses a newer DB), and the full `ProjectService` flow suite (in-memory SQLite + a `FakeLauncher`: dup-name/dir reject, best-effort create, open missing-dir / missing-app / success+`mark_opened`, all-or-nothing refresh, bin-only delete guard, `delete_directory` both branches, restore, inspect-bad-dir, `ensure_project` idempotency). Frontend: `svelte-check` (`pnpm run check`) plus a `vitest` suite (`pnpm test`) — `src/lib/trackers.test.ts`, 14 tests over `trackers.ts` field-type inference and `trackerColor()`.

## Dependencies of note

- **`indexer-core`:** `git2` (libgit2 bindings, `Gitector`), `rusqlite` with `bundled` (SqliteRepository — compiles SQLite in, needs a C compiler at build time), `serde` / `serde_json` (models + `.uproject` parsing + the blob store), `chrono`, `uuid`, `thiserror`. Windows-only: `winreg`, `parselnk` (Start-Menu `.lnk` resolution for the app picker).
- **`src-tauri`:** `tauri` + `tauri-plugin-dialog/shell/opener/global-shortcut/single-instance/window-state` and `indexer-core`. No `tauri-plugin-store` (dropped with the SQLite swap), and `serde_json` / `chrono` / `uuid` / `thiserror` were removed too — the GUI crate has no models or errors of its own any more. The dead `@tauri-apps/plugin-store` npm dependency was dropped from `package.json` as well.
- **JS toolchain:** pnpm (`packageManager: pnpm@11.21.0`; `beforeDevCommand` / `beforeBuildCommand` are `pnpm dev` / `pnpm build`; no `package-lock.json`).
